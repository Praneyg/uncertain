# Criterion 25 — LLM-graded usability

**Grader:** the same model (Claude) that built this eval suite, working only from
`eval/usability_evidence.md`. That file is generated by `eval/usability_evidence.py` and holds the
public names, signatures and docstrings, the errors raised for each axis, and the README. The grader
is therefore not independent of the evaluation. Re-grade with another model or a human for an
unbiased score.

**Rubric (per axis, 1–5):**
5 — discoverable from the public signature and docstring alone, with a correct example;
3 — discoverable, but only by reading another module or the docs, or the docs are partly wrong;
1 — not discoverable without reading the implementation. 2 and 4 are in-between scores.

The main entry point is `Measure.from_config`, the only public callable whose docstring names the
axes. `Measure`, `Measure.compute`, `Measure.replace`, `Sweep`, `Sampler.sample/extend`, and the
presets `surprisal`, `information_value`, `entropy` and `contextual_probability` have **no
docstrings**. The spec dataclasses show only their auto-generated signatures.

## unit
Evidence: the signature has `unit='token'`. The docstring says only "Configure a measure along
independent scientific axes". The misuse error `ConfigError: Unknown unit: morpheme` does not list
the valid units. The README says "Token units and explicit `whitespace:v1` word / `punctuation:v1`
sentence detectors". The axis exists in the signature, but the three valid values and the "one
unit per run" rule come only from the README and docs.
<score axis="unit">3</score>

## horizon
Evidence: the signature has `horizon=1`; the README shows `measure.replace(horizon=3)`. Nothing in
any docstring says H counts *units*, not tokens. That is the axis's main semantic point (§4.2), and
it is in neither the docstring nor the README. The error `horizon must be a positive integer` is
clear.
<score axis="horizon">3</score>

## level (representation)
Evidence: the signature has `representation='tokens'` and `level=None`. The docstring says
"representation and statistic also accept their full specs" but names no encoder (`tokens`,
`strings`, `layer:N`). The `"layer:8"` string form and the pooling options appear only in
`docs/api.md` / `docs/configuration.md`. With a backend that has no hidden states, the error is
clear (`layer encoder requires a backend with hidden representations`). Valid values need a
separate doc file.
<score axis="level">2</score>

## distance
Evidence: the signature has `distance='discrete'`. The README lists "Prefix indicator, n-gram
overlap/distance, discrete, cosine, and Euclidean scores" in prose, not as the registry strings
(`prefix_indicator`, `ngram_overlap`, `ngram_distance`). The mismatch error
`encoder units incompatible with distance vector` names the *types*, not the components. §6.1
asks the error to name "the offending pair".
<score axis="distance">3</score>

## aggregation (statistic)
Evidence: the signature has `statistic='energy'`. The README lists "mean, directed minimum, and
V/U energy statistics". The error for an unknown name, `Unknown statistic: median@1`, does not
list the valid names. Neither a docstring nor the README says that energy needs a negative-type
distance, though the config error does. The `variant="v"/"u"` choice and its bias are in
`docs/` only.
<score axis="aggregation">3</score>

## set size
Evidence: `n` is a required keyword with no default. The docstring says "``n`` and
``short_samples`` are required (§4.4, §4.2): how many alternatives a measure rests on … never
defaults". The README example passes `n=512` and runs (it is the same call the suite exercises).
Omitting `n` gives `TypeError: … missing 1 required keyword-only argument: 'n'`.
<score axis="set size">5</score>

## short-sample policy
Evidence: `short_samples` is a required keyword, and the docstring says so. The bad-value error
lists the choices (`short_samples must be pad, drop, or compare_ragged`), and so does the README.
No docstring says what each policy *does*, and nothing says layer encoders reject `pad`. The
values are discoverable from the signature and errors; the semantics are not.
<score axis="short-sample policy">4</score>

**Mean: 3.3 / 5.** Set size and short-sample policy are discoverable from the API, as §4.4/§4.2
intend. Level, distance and statistic names need the docs.
